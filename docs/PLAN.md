# FreeTokens — план проекта

Windows-приложение для агентной работы с ИИ через веб-чаты в локальном браузере —
бесплатно, без API-ключей. Приложение отправляет запрос в браузер через расширение,
получает ответ, имеет доступ к файлам ПК и умеет полноценно вести разработку
(править файлы, запускать команды, итерироваться по результатам).

## Зафиксированные решения (2026-11-16)

| Вопрос | Решение |
|---|---|
| Стек приложения | C# / .NET (последний LTS), **WPF**, MVVM (CommunityToolkit.Mvvm) |
| Провайдер №1 | **DeepSeek** (chat.deepseek.com), ChatGPT — позже (M4) |
| Мост в браузер | Chrome MV3-расширение на **playwright-crx**, связь с приложением по WebSocket (127.0.0.1 + токен) |
| UI v1 | Средний: чат, дерево файлов, предпросмотр диффов, панель подтверждений |

## Архитектура

```
┌─────────────────────────────────────────────┐
│ FreeTokens.App (WPF, .NET)                  │
│                                             │
│  UI: чат │ дерево файлов │ диффы │ подтверж.│
│  Ядро агента (цикл задача→действия→результат)│
│  Провайдеры: IChatProvider → DeepSeek        │
│  Инструменты: файлы, команды, журнал отката │
│  SQLite: история, настройки                  │
│  WebSocket-сервер 127.0.0.1:<port>           │
└──────────────────┬──────────────────────────┘
                   │ JSON over WS (токен-аутентификация)
┌──────────────────┴──────────────────────────┐
│ Расширение Chrome (MV3, TypeScript)         │
│  background.ts — WS-клиент, роутер команд   │
│  playwright-crx — attach к вкладке DeepSeek │
│  deepseek.ts — операции чата                │
└──────────────────┬──────────────────────────┘
                   │ автоматизация вкладки
        ▼ chat.deepseek.com (сессия пользователя)
```

Логин в DeepSeek выполняется вручную один раз в обычном браузере — расширение
работает с уже залогиненной сессией.

## Компоненты

### 1. FreeTokens.App (WPF)

- **Bridge** — WebSocket-сервер на localhost (ASP.NET Core Kestrel in-process),
  генерация токена при первом запуске, показ порт/токен в настройках для ввода
  в options-страницу расширения.
- **Ядро агента** — цикл: задача → сборка промпта → провайдер → парсинг
  действий → выполнение инструментов → результаты обратно модели → …до `<final>`
  или лимита итераций. Стоп/пауза задачи.
- **Провайдеры** — `IChatProvider`: `SendAsync(prompt) → IAsyncEnumerable<delta> + result`.
  `DeepSeekWebProvider` ходит через мост.
- **Инструменты** — `read_file`, `write_file`, `list_dir`, `search`, `run`.
  Всё в пределах рабочей папки; `write_file`/`run` — только после подтверждения
  в UI. Перед перезаписью — сохранение оригинала в журнал отката
  («отменить всё за задачу»).
- **Данные** — SQLite: история чатов, журнал действий, настройки.

### 2. Расширение (TypeScript + playwright-crx)

- `background.ts`: подключается к `ws://127.0.0.1:<port>` (порт/токен из options),
  переподключение с backoff, ping каждые ~20 с (не даёт MV3 service worker уснуть).
- `deepseek.ts`: операции — найти/открыть вкладку, новый чат, тумблер DeepThink,
  вставка промпта (симуляция paste — надёжнее посимвольного ввода в contenteditable),
  ожидание завершения (кнопка stop→send + стабильность DOM), извлечение markdown
  (кнопка Copy + буфер; фолбэк — innerText контейнера ответа), детект ошибок
  (не залогинен / капча / лимит).
- `selectors.ts`: ВСЕ селекторы DeepSeek в одном файле — чинится за минуты.
- `protocol.ts`: типы сообщений — единый источник, вручную зеркалится в C#.

### 3. Протокол моста (JSON over WS)

App → Ext:

| Сообщение | Назначение |
|---|---|
| `{id, op:"ping"}` | keepalive / health |
| `{id, op:"getStatus"}` | вкладка, залогинен ли, готов ли |
| `{id, op:"openChat", newChat:true}` | открыть / создать чат |
| `{id, op:"setMode", mode:"deepthink"\|"normal"}` | тумблер DeepThink |
| `{id, op:"sendPrompt", text}` | отправить и ждать ответ |
| `{id, op:"cancel"}` | прервать генерацию (клик stop) |

Ext → App:

| Сообщение | Назначение |
|---|---|
| `{id, type:"result", markdown}` | полный ответ |
| `{id, type:"delta", text}` | частичный текст (стрим в UI) |
| `{id, type:"error", code, message}` | `notLoggedIn` / `captcha` / `rateLimited` / `selectorNotFound` / `timeout` |
| `{type:"event", name:...}` | события без запроса (вкладка закрыта и т.п.) |

### 4. Агентный протокол (формат ответов модели)

Системный промпт требует строгий формат; ядро парсит блоки:

```
<action tool="read_file" path="src/App.xaml.cs"/>
<action tool="list_dir" path="src"/>
<action tool="search" query="regex" path="src"/>
<action tool="write_file" path="src/App.xaml.cs">
…полное содержимое файла или unified diff…
</action>
<action tool="run" cwd=".">dotnet build</action>

<final>краткое резюме, что сделано</final>
```

Результаты возвращаются модели следующим сообщением:

```
<result tool="run" ok="false" exit="1">
…вывод команды, обрезанный до N символов…
</result>
Продолжай.
```

Правила: до 10 файлов в промпте-контексте (только нужные фрагменты), вывод
команд обрезается, лимит итераций на задачу (настраивается, по умолчанию ~25).

## Специфика DeepSeek (проверить на спайке)

- Композер: contenteditable/textarea — выбрать способ вставки (paste-симуляция).
- Индикатор генерации: кнопка «отправить» ⇄ «стоп».
- Кнопка Copy у ответа копирует сырой markdown — основной способ извлечения.
- Сообщения о лимитах/нагрузке — собрать точные строки для детекта.
- Все селекторы — предварительные, сверить с живым DOM на M0.

## Этапы

### M0 — Спайк: доказать туннель ✅ (2026-11-16)

Выполнено полностью: промпт из консоли C# → расширение (playwright-crx) →
chat.deepseek.com → ответ обратно в консоль. Полный цикл ~4с, стрим-дельты работают.

Зафиксированные факты о DOM DeepSeek (проверено 2026-11-16):
- композер — единственный `textarea[placeholder]` (placeholder локализован, id отсутствует);
- тело ответа ассистента — `div.ds-markdown` (до первой отправки блоков в DOM нет);
- кнопки — без aria-label/testid (обфусцированные классы) → детект завершения
  только стабильностью текста, Copy-кнопку искать по позиции внутри блока сообщения.

Инфраструктура: `dotnet run -- auto` — e2e-тест; `auto dump` — дамп DOM для
настройки селекторов; `tools/fake-ext.mjs` — тест моста без Chrome.
Грабли, на которые наступили: подпротокол WS (клиент может не предлагать —
соглашаемся на null), MSYS-конверсия `/флагов` в пути (флаги без слэша),
fire-and-forget задачи глотают исключения (наблюдать фолты).

### M1 — MVP-чат ✅ (2026-11-17)
- Решение: `src/Core` (мост), `src/App` (WPF, MVVM, CommunityToolkit), `src/Cli` (REPL/e2e).
- WPF-приложение: список чатов, лента сообщений со стримом, статус моста, настройки
  (порт/токен/рабочая папка), история в SQLite (%AppData%\FreeTokens\freetokens.db),
  схема сразу с полями под агентов (M4).
- Расширение: op `openChat` (новая сессия DeepSeek), `sendPrompt` возвращает url чата.
- Тумблер DeepSeek DeepThink — перенесён в M2 (кнопки без aria-label, нужен подбор по позиции).
- Регрессия после рефакторинга: probe+sendPrompt через Cli — 4,8с.

### M2 — Агентный режим ✅ (2026-11-17, код; приёмка — руками)
- Протокол действий: `<action tool="list_dir|read_file|search|write_file|run" …/>` + `<final>`;
  парсер — `Agent/ActionParser.cs`, промпт — `Agent/SystemPrompts.cs` (со структурой рабочей папки).
- `Agent/AgentRunner.cs`: цикл до 25 итераций; каждый ход модели — ответ в ленте,
  действия — карточками 🔧, результаты — `<result …>` обратно модели.
- `Tools/ToolExecutor.cs`: песочница (канонический путь внутри рабочей папки),
  лимиты (read 50КБ, list 300, search 50 совпадений, run 60с + kill дерева),
  cmd с кодировкой cp866.
- Подтверждения: `ConfirmWindow` — дифф (SimpleDiff, LCS) для write_file, текст команды для run.
- Журнал отката: таблица `file_versions`, кнопка «↩ Откат» (восстановление в обратном порядке).
- UI: чекбокс «Агентный режим», кнопка «■ Стоп» (между итерациями), панель «Файлы проекта»
  с ⟳ и ↩. Песочница для тестов: `sandbox/`.
- Ограничения: останов срабатывает между ходами (не во время генерации DeepSeek);
  ходы агентного диалога не пишутся в историю (только финал); markdown не рендерится.

### M3 — Робастность и контекст ✅ (2026-11-17, код; включается перезапуском приложения)
- Ротация контекста: после ~60 тыс. символов за сессию агент сам просит у модели резюме,
  открывает новый чат DeepSeek и продолжает с «ПРОДОЛЖЕНИЕ РАБОТЫ + РЕЗЮМЕ» (🔄 в ленте).
- Ретраи ходов: таймаут SW при живом соединении — повтор; ошибки провайдера
  (timeout/rateLimited/internal) — пауза 30с и повтор; обрыв соединения — ожидание
  переподключения до 60с (из M2-фикса).
- Кнопка «🩺 Диагностика»: соединение + getStatus + probe с человекочитаемым разбором.
- Кнопка «⟳ Расширение»: горячая перезагрузка кода расширения (`chrome.runtime.reload()`) —
  SW вечно живёт при активном WS и сам dist не перечитывает.
- Файловый лог `%AppData%\FreeTokens\log.txt` (ротация 2МБ), события `[ext:op]` от расширения.

### M4 — Агенты и оркестратор

**Агент** = профиль + выделенный чат провайдера:
- роль (Планировщик / Разработчик / Ревьюер / Тестировщик / пользовательские);
- системный промпт, режим DeepThink, лимит итераций, доступные инструменты;
- свой чат DeepSeek со своим контекстом (`chats.agent_role`, `chats.system_prompt`
  в схеме SQLite уже зарезервированы с M1; `provider_chat_url` привязывает
  локальный чат к сессии провайдера).

**Оркестратор** — диспетчер над агентами:
- очередь задач: разбивает входящую задачу на подзадачи и назначает агентам;
- маршрутизация: результат одного агента → вход другого (например, Планировщик → Разработчик → Ревьюер);
- ротация контекста: при переполнении чата создаёт новый и переносит компактное резюме;
- контроль параллелизма: одна вкладка = одна генерация; параллельные агенты = несколько вкладок
  (с ограничением и учётом лимитов DeepSeek);
- наблюдаемость: трассировка цепочки сообщений между агентами в UI.

Прочее из M4: адаптер ChatGPT + фолбэк провайдеров, git-интеграция, библиотека промптов.

## Риски

| Риск | Митигция |
|---|---|
| playwright-crx — экспериментальный API | тонкая обёртка в одном модуле; при проблемах переходим на голые `chrome.*` API без смены архитектуры |
| Селекторы DeepSeek ломаются при обновлениях | все в `selectors.ts`, фолбэки, режим диагностики |
| MV3 service worker засыпает | ping ~20 с, авто-переподключение WS |
| Бан аккаунта | отдельный (не основной) аккаунт, человечные тайминги, без параллельных чатов; автоматизация веб-чата формально нарушает ToS |
| Лимиты/нагрузка DeepSeek | детект сообщений о лимите, пауза/повтор, позже фолбэк на ChatGPT |
| Переполнение контекста веб-чата | ротация чатов + резюме, только фрагменты файлов |
| Опасные действия агента | подтверждения в UI, песочница = рабочая папка, журнал отката, allowlist команд |
